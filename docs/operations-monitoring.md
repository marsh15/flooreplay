# Operational evidence and interruption policy

The owner Operations view answers: which request failed, which saved provider operation it belongs to, whether billing is uncertain, and which reservation remains committed. It reads actor-scoped metadata and never includes source text, questions, credentials or raw request paths. Request IDs are generated by the server, returned as `X-Request-ID`, persisted with route templates and latency, and pinned into generation configuration. Host logs use JSON receipts. Searching a request, incident or operation ID filters the visible receipt window.

A 5xx receipt raises a page alert in the application: search its request ID in host logs, check readiness and the deployed commit, then inspect related saved operations before retrying. A provider operation whose reservation expired becomes `UNCERTAIN`; its reservation remains committed. Search the operation ID and provider receipt IDs, reconcile actual billing manually, and do not submit new paid work while the original charge is uncertain. Invalid, incomplete and unavailable drafts raise ticket alerts; use the deterministic report while examining the saved failure.

Alerts are an in-application feed, not an externally delivered pager. A database outage can prevent receipt persistence; the host JSON log is the fallback. The list has a bounded recent window and does not establish long-term retention or a latency SLO. Thresholds for terminal failure and retained uncertain spend are exact states, not speculative latency thresholds.

Generation already persists identity, packet, reservation and running state before invoking a provider outside the transaction. It has a 60-second execution budget and at most two attempts for structurally invalid completed output. Interrupted connections do not trigger a retry. Existing request identity reuse does not dispatch another generation. Adding a queue would not eliminate ambiguous provider billing, so this release keeps the bounded request path and makes interrupted operations inspectable. A worker would be justified only by measured deployment timeout/throughput requirements, with the same uncertainty boundary retained.

Local injected-failure tests locate a failed import route through its returned request ID while proving raw IDs and query secrets do not enter receipts. Stale-run tests verify repeated inspection retains the same uncertain status and spending reservation without calling a provider. Hosted alert delivery and incident response need actual deployment evidence; local tests do not establish them.

Unexpected exceptions return a sanitized 503 with the same request ID in the error body and response header. Uvicorn's raw access logger is disabled because query strings may contain private search text; the application's allowlisted JSON receipts replace it. Hosting ingress logs remain a separate configuration responsibility. Readiness exposes the checked schema revision and configured build identity for release/restart diagnosis.
